- 重整评论与正文的绑定方式：正文下载时为每个微信 `range` 建立持久定位索引；评论内容仍独立保存在 `thoughts.sqlite3`，获取、刷新或删除评论都不会重新生成 EPUB。
- 评论可在正文完成后的任意时间按范围获取：阅读中支持本章、从本章开始 5/10 章、选择章节、全部已有正文和整本；主页评论入口支持前 5/10 章、选择章节、全部已有正文和整本。
- 完整正文与章节正文共用同一评论核心；章节模式只允许对本机已有正文的章节获取评论，阅读时下一章评论预加载也只处理已有正文章节。
- 评论获取优先复用正文阶段保存的 `bookId + chapterUid + range`，不再每次重新获取划线；强制刷新时才重新读取 underlines，并把后来新增的 range 作为运行时定位补入。
- 修复“range 已返回但评论正文为 0”仍被误判成功的问题：Web 结果缺失或语义为空都会交给旧 Gateway 复核；未验证空结果继续待补，不能写成完成。
- beta.10～beta.12 遗留的 `0 评论 + complete=true` 状态升级后自动作废为待重新确认；已有非空评论不会被异常 0 条结果覆盖。
- 新增安全的评论接口诊断统计，只记录请求 range、返回组数、实际评论数和回退结果，不记录 Cookie、凭据或评论正文，便于实机直接判断 Web / Gateway / SQLite 哪一层异常。
- 新下载正文把成功对齐和未能嵌入的 range 都写入 locator 索引，并保存正文指纹；正文重新生成时仅重建定位，不删除评论缓存。
- 新正文中的所有微信读书划线统一恢复为 Kindle/CREngine 兼容的 `border-bottom: 1px dashed #000` 虚线；评论是否已下载不再改变线型。
- 运行时划线层只负责旧正文或正文生成后新增的 `embedded=false` range；已经嵌入 EPUB 的 range 不再重复绘制，避免实线、双线和重复点击区。
- 正文中的评论链接继续使用同一个 range；点击尚未下载评论的虚线时会提示“获取本章评论 / 继续补全”，获取成功后无需重新下载正文。
- 删除本章、本书或全部评论缓存只删除评论数据和获取状态，持久 locator 保留；评论收藏、正文、阅读记录和用户批注继续独立。
- 下载时选择评论预加载后，正文 100% 不再提前关闭下载窗口；所选评论范围完成或明确待补后，本次下载才进入最终完成状态。
